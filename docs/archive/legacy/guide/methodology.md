# 方法论:从「用户中心」项目提炼的全部哲学

> **结论先行**:用户中心项目(一本书 + 一个跑通的全栈系统)能成,靠的不是技术,而是一套**可复制的方法**。本文把它提炼成 10 条,任何新项目(包括电子书 App)照做即可。

原项目:<https://github.com/wohuishuo/user-center-team-project>(网页书 + Spring Boot/React 实现 + 课程文档,全部闭环)

---

## 一、核心哲学(为什么这么做)

### 1. 书与项目互证闭环

**结论**:先写书讲清"该怎么做",再严格照书实现,书中每章链接真实代码,实现中踩的坑回流进书。

**根据**:只写书,知识悬空没验证;只写代码,半年后没人看得懂为什么。书↔代码互相印证,两边都更可信。

**例子**:用户中心书里"认证模块"章末尾的「本章的真实代码」表格,直接链到 `UserServiceImpl.java`;而实现时踩的 JDBC 编码 bug,反过来写进了书和测试报告。

### 2. 金字塔 / 一分钟说话(全部写作的地基)

**结论**:每段表达都是三层——**结论 → 根据 → 例子**;一分钟说不清的,三小时也说不清。

- 结论先行,加粗放最前;
- 用「我们」不用「我」,读者中心,不搞纵向压制;
- 听众只记住 10%,图是补充不是主角,太复杂的图会抢走注意力;
- **写完检查逻辑链**:结论真的由根据推出吗?例子真的支撑根据吗?

### 3. 直接路径(理工科作文原则)

**结论**:直接告诉读者"现在该怎么做",不复述"我怎么一步步发现的",不做新旧版本对比。

**根据**:读者要的是结果的最短路径。省下的篇幅,拿去写新东西的**具体细节**——这才是增量价值。

**例子**:用户中心书里讲密码,直接说"用 BCrypt,这样写",一句话带过为什么,绝不铺陈"MD5 的历史与演变"。

### 4. 思考的定义

**结论**:思考 = 知识(内在信息)+ 消息(外在信息)→ 结论。每个金字塔的"结论"都该这样产生,而不是凭空主张。

## 二、工程方法(怎么做项目)

### 5. 里程碑驱动:M0 → M8,每步可验证

**结论**:把项目切成 8 个里程碑,**每个都以"真实验证通过 + commit + push"收尾**,绝不积压。

```
M0 环境 → M1 需求 → M2 数据设计 → M3 工程骨架
→ M4 核心功能① → M5 核心功能② → M6 界面/联调 → M7 测试+文档 → M8 部署
```

**根据**:每个里程碑都能跑、都有产物,随时可以停下也随时可以继续;问题在最小范围内暴露(最左原则)。

**例子**:用户中心每个 M 结束都有实测记录——M4 是"DB 里密文以 `$2a$` 开头",M8 是"四个容器 healthy + 经 Nginx 注册成功"。**口头"做完了"不算,跑给自己看才算。**

### 6. 先完成,再优化;先骨架,再血肉

**结论**:先让最小版本跑起来(健康检查、一个页面、一条数据),再逐步加功能。

**反例(亲历)**:上一个 Android 项目"把课件全学完再动手",结果学了大半个月、开发只剩三周、只完成数据库层。**课件按需查,代码尽早跑**。

### 7. 公共件先行,安全为先

**结论**:动业务之前,先把工程公共件立好;安全规则从第一行代码就遵守。

- 公共件:统一返回结构、全局异常处理、常量(不留魔法数字)、分层职责(格式校验在入口层、业务校验在服务层);
- 安全:密码必加密(BCrypt 类慢哈希)、返回必脱敏、错误提示模糊化、**前端隐藏 + 后端鉴权双保险**、机密走环境变量绝不进 Git。

### 8. 文档从模板长出来,用真实内容填

**结论**:课程文档不另起炉灶——提取课程模板的大纲,用项目的**真实**设计与数据填进去。

**例子**:用户中心的《软件测试报告》里写的缺陷,是真实发生的 `characterEncoding` bug 及其定位修复全过程——比编造的"无缺陷"可信得多,这正是老师想看的。

## 三、协作方法(人与 AI 怎么配合)

### 9. AI 出力,人定方向与守闸门

**结论**:AI 负责生成骨架、写测试、查资料;人负责说清目标、给够上下文、**改完自己跑一遍**。

- AI 的盲区是"全局连带":它改 B 时看不见 C 依赖 B 的参数——所以**验证永远由人兜底**;
- 给 AI 报错时给**原文 + 复现步骤**,不说"它坏了";
- 关键约定写进 `CLAUDE.md`,让 AI 每次都看到。

### 10. 降低他人使用门槛(项目的最后一公里)

**结论**:做完 ≠ 别人能用。必须配齐:README 写清**怎么跑**(两种方式:一键 Docker / 本地开发)、**内置演示账号**、一键启动脚本、功能演示幻灯片、踩坑记录(DEV-SETUP)。

**例子**:用户中心内置 `root/12345678`,任何人 clone 后 `docker compose up` 就能以管理员身份体验——"下载了不知道咋用"被彻底消灭。
