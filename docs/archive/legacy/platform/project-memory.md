# 项目记忆库:防止老坑重复出现

> **结论先行**:这个文件是 BookRealm 的工程记忆,不是普通日志。凡是用户反复指出、模型容易忘、会导致返工的问题,都写在这里。后续任何 AI 接手,先读本页再动 App。

## 一、当前真实状态

**BookRealm 仍是 `0.3.0-alpha.20260616`。**

它已经能跑通登录、书架、阅读、AI、划线、笔记、段评和点赞,但还不是 beta。原因很简单:读者不用说明也能顺手使用之前,不能叫成熟版本。

## 二、版本纪律

**产品版本要慢。工程阶段可以快。**

| 场景 | 用什么编号 | 例子 |
| --- | --- | --- |
| App、README、Release | 产品版本 | `0.3.0-alpha.20260616` |
| 工单、平台书、内部路线 | 工程阶段 | `v2.2 阅读互动` |
| 小修复、小体验整理 | patch / alpha 说明 | `0.3.x-alpha 产品化修补` |

禁止把“做了一批工单”直接写成 beta。beta 至少要满足:返回逻辑顺、搜索边界清楚、阅读设置记忆、我的页入口可用、核心链路有真机自动验收。

## 三、反复出现的老坑

### 1. 顶部重复标题

**结论**:不要在书架、书城、我的页同时出现系统顶栏标题和页面大标题。

用户已经多次指出“书域 / 书架 / 我的”出现在上方很怪。主页型页面应该优先使用内容自己的搜索框、阅读打卡、模块标题,而不是一条孤立的大 AppBar 标题。

验收口径:

- 书架顶部优先是搜索框和继续阅读,不是“书架”大字;
- 书城顶部搜索与书架搜索视觉统一;
- 我的页不要上面写“我的”,中间又写一遍“我的”。

### 2. 书架直接阅读的返回

**结论**:从书架点书进入阅读,返回必须回书架;从详情页目录进入阅读,返回才回详情。

这是第二次重复踩坑。不能只靠 `selectedBook` 猜来源,需要状态里明确记录阅读入口来源。

### 3. 划线面板关闭

**结论**:点击已划线文字打开操作面板后,用户必须能轻松关闭。

关闭规则:

- Android 返回键:只关闭划线操作面板;
- 点击阅读空白处:关闭划线操作面板;
- 再次点击同一条划线:关闭划线操作面板;
- 只有面板关闭后,再次返回才退出阅读。

### 4. 搜索边界

**结论**:书架搜索只搜自己的书架;书城搜索才搜全站。

书架点搜索跳书城会让用户觉得 App 抢方向。可以提供“去书城搜索”入口,但不能把本地搜索和全站搜索混成一个行为。

### 5. AI 结果和 RAG 依据

**结论**:AI 页面要回答用户问题,不是把 RAG 原文直接倒给用户。

没有模型 key 时可以明确说“当前返回依据”;有模型 key 时优先展示回答,引用依据放后面。AI 临时窗口、bubble、摘要入口不能重复显示同一段内容。

### 6. 自动化测试口径

**结论**:启动成功不是功能测试。

当前 `adb-smoke.ps1` 只证明 App 能安装、启动、主要 UI 标记存在。下一步必须扩展成真实点击链路:

1. 书架搜索;
2. 打开阅读;
3. 长按段落;
4. 保存划线;
5. 点击划线;
6. 关闭面板;
7. 返回书架。

## 四、接手前检查清单

- 先读 `TODO-总进度.md`、本页、`docs/platform/versioning.md`;
- 后端相关先读工程治理五件套:`architecture-review.md`、`adr-001-unified-auth.md`、`api-reference.md`、`testing-strategy.md`、`runbook-platform-ops.md`;

- 能用稳定 `testTag` 测的地方,不要用中文文本做核心断言;
- 每次修复用户指出的重复问题,把规则写回本页。

## 五、后端治理裁决

**结论**:三个后端服务结构健康,但鉴权不是小瑕疵,是下一个后端工单的红线。

2026-06-16 的架构评估确认:

- `br-library-service`、`br-event-stats`、`br-ai-service` 分层一致、依赖较新、可继续演进;
- 真实实现与 P7 有漂移:MQ 是 `user.events`,阅读进度走 HTTP;P7 已加警告,不再假装图就是代码;
- 当前后端不验 JWT,`userId` 由客户端传,存在越权风险;
- ADR-001 状态是 Proposed,还没有实施。任何人不能把"写了 ADR"说成"已经安全"。

下一步后端优先级:

1. 落地 ADR-001 统一鉴权;
2. 补越权负向测试;
3. 再处理 RAG 持久化、接口幂等、API 网关等演进。
