# 参考项目复用策略

> **结论先行**:参考项目和截图都应该进入 BookRealm 的知识库,但不能粗暴复制。开源项目主要学架构、功能拆分和交互模式;商业 App 截图只学信息结构和体验目标;真正代码必须按 BookRealm 的技术栈重写。

## 一、为什么不能直接拿

**结论:直接拿代码会带来许可证、维护和架构三类问题。**

| 来源 | 能不能直接复制代码 | 原因 |
| --- | --- | --- |
| Legado / 阅读 Sigma / 阅读 R | 不建议 | 这些项目是 GPL-3.0 系,直接复制代码会带来强开源义务;而且架构很重 |
| Hoshi Reader Android | 不建议 | GPL-3.0;可以学竖排、词典、跟读,但不要搬代码 |
| ReadAny | 不建议 | GPL-3.0;技术栈是 TypeScript/Expo/Tauri,和我们的 Compose/Spring 路线不同 |
| 微信读书/起点截图 | 不能 | 商业 App 视觉和截图不能放进公开仓库,也不能像素级复刻 |
| 本地 `tts pre` | 可以重构复用 | 这是我们自己的资产,但要拆成 Python Worker + Spring 服务 |

## 二、我们真正要复用什么

**结论:复用“知识”,不复用“外壳”。**

可以复用:

- 页面结构:书架、详情页、阅读页、设置页怎么分层;
- 交互流程:点击正文唤起工具层、选区菜单、目录底板、听书浮层;
- 功能清单:竖排、分页、词典、高亮、TTS、导入、统计;
- 数据模型思路:书、章、段、笔记、划线、词典项、朗读任务;
- 工程策略:本地缓存、任务队列、导入管线、可观测控制台。

不能复用:

- 原项目源代码;
- 原项目图标/图片/品牌视觉;
- 商业 App 的具体排版、文案和运营素材;
- 版权不清的书源/抓取规则。

## 三、参考项目拆解

### 1. Legado 系

**学什么**:

- 书架列表/网格切换;
- 本地 TXT/EPUB;
- 主题、字体、背景、行距、段距;
- 多翻页模式;
- 书源规则的“能力边界”。

**不直接做什么**:

- 不做盗版书源聚合;
- 不搬规则引擎代码;
- 不复制它的重型架构。

**BookRealm 落点**:

- v2.1:阅读设置;
- v2.5:EPUB/TXT 导入;
- v2.x:分页/滚动/竖排。

### 2. Hoshi Reader Android

**学什么**:

- 竖排/横排阅读;
- 分页/连续滚动;
- Yomitan 式词典弹窗;
- 递归查词;
- 五色高亮;
- audiobook read-along。

**不直接做什么**:

- 不做日语学习专用字段系统;
- 不做 Anki 制卡第一版;
- 不做 Google Drive 同步第一版。

**BookRealm 落点**:

- v2.2:选区词典 + AI 解释;
- v2.3:朗读跟读;
- v2.x:竖排/横排。

### 3. ReadAny

**学什么**:

- AI 阅读不是聊天按钮,而是语义搜索、知识管理、笔记整理;
- 多端产品应该围绕“读完后留下什么”设计;
- AI 与笔记、搜索、导出可以形成闭环。

**不直接做什么**:

- 不先做 Tauri 桌面端;
- 不先做全格式阅读器;
- 不复制 TypeScript/Expo 架构。

**BookRealm 落点**:

- v2.2:AI 解释选中文字;
- v2.6:语义搜索和推荐;
- v3:知识管理。

### 4. 微信读书/起点截图

**学什么**:

- 微信读书:阅读器工具层、划线菜单、听书浮层、详情页结构;
- 起点:书架信息密度、长篇目录、段评气氛、详情长页。

**不直接做什么**:

- 不复制商业视觉;
- 不复制付费、会员、活动入口;
- 不把截图放进 GitHub。

**BookRealm 落点**:

- v2.1:书架、详情页、阅读工具层;
- v2.2:划线、段评、词典;
- v2.3:听书浮层。

## 五、工作流

**结论:以后每个参考能力都走 5 步,不要凭感觉搬。**

1. 收集截图或项目链接;
2. 写三行分析:解决什么、学什么、不学什么;
3. 归入能力层:阅读、AI、导入、TTS、社区、推荐、商业、工程;
4. 写进小 MVP 工单;
5. 用 BookRealm 代码重写并验证。

这就是“知识数据库”的用法:它不是素材仓库,而是决策仓库。
