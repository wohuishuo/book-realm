# BookRealm 产品愿景

> **结论先行**:BookRealm 要证明的不是“功能最多的阅读 App”,而是一套可信、可解释、可持续演进的现代阅读体验。

## 用户问题

**结论**:读者的阅读、理解和记录经常被拆散在不同工具里。

读者在阅读中遇到不懂的原文时需要切换搜索工具;划线、笔记、阅读位置和 AI 对话又各自散落。对课程和求职展示而言,只有能跑的界面也无法证明需求、设计、测试和决策形成了闭环。

## 产品承诺

**结论**:BookRealm 把“找书、持续阅读、留下痕迹、基于原文理解”连接成一条主旅程。

```text
登录 → 找到一本书 → 加入书架 → 持续阅读
    → 划线/笔记/段评 → 基于原文向 AI 提问 → 回到引用位置
```

## 目标用户

| 用户 | 核心结果 |
| --- | --- |
| 普通读者 | 不看说明也能完成阅读主旅程 |
| 课程老师 | 能从需求追溯到架构、代码和测试证据 |
| 开发者 | 能快速找到当前范围、决策和下一任务 |
| 学习者/面试官 | 能理解项目为什么这样设计,而不只看到技术清单 |

## 产品原则

1. 阅读主流程优先于功能数量。
2. AI 回答必须尽量基于并引用原文。
3. 用户数据身份由服务端验证,不信任客户端声明。
4. 已实现功能必须有可重复的验收证据。
5. 产品正本、代码事实和工作状态各有唯一来源。

## 非目标

当前不以商业化为目标,不优先建设支付、版权运营、复杂推荐、直播社区和大规模内容后台。它们只有在主旅程达到 1.0 后才进入评估。
