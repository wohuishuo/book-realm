# 书的重读整理清单(RC 阶段)

> **结论先行**:每本书写完不算完——必须经过一次**冷却后的重读整理**(Review & Consolidate,简称 RC),用下面三层清单逐项检查,全过才打 v1.0 标签。金字塔搭好了,还要从上往下重走一遍,确认每一级都接得住上一级。

**用法**:把本文件复制进每个 MVP 仓库;书初稿完成后**冷却至少 2 天**(让自己变回"读者"),然后按清单过;每查完一层在方框打勾;AI 可以做第一轮(让它逐章挑逻辑断点),**人做终审**。

---

## 第一层:逐章检查(每一章单独过)

- [ ] **结论先行**:开头第一段就是本章结论(加粗),不是背景铺垫?
- [ ] **逻辑链完整**:结论真的由"根据"推出来?根据之间不重叠、不矛盾?
- [ ] **例子真实**:例子来自我们项目的真实代码/真实操作,不是编的?
- [ ] **一分钟测试**:只读本章的结论句,能在一分钟内向别人讲清这一章吗?
- [ ] **直接路径**:有没有"我们先试了 X 后来才发现 Y"式的过程叙述?删掉,直接给 Y。
- [ ] **读者口吻**:用「我们」;没有居高临下;术语首次出现有解释?
- [ ] **图是补充**:图比文字简单,而不是更复杂?每张图有一句话说明它说明了什么?
- [ ] **代码可信**:「本章的真实代码」链接都指向真实文件且未失效?

## 第二层:全书检查(整本串起来过)

- [ ] **顺序递进**:按目录顺序读"每章结论句",它们连成一个通顺的故事吗?(这是全书的金字塔)
- [ ] **无断层**:有没有哪章用了前面没讲过的概念?要么补链接,要么调整章节顺序。
- [ ] **无重复**:两章讲了同一件事?合并或一处讲透、另一处只放链接。
- [ ] **粒度一致**:有没有某章特别臃肿或特别空?拆分或充实。
- [ ] **导航一致**:侧边栏顺序 = 学习顺序;每章末尾的"对应资源"链接都有效?
- [ ] **TODO 清零**:全文搜索 `TODO`、"待完成"、"占位",处理干净。
- [ ] **构建通过**:`npm run docs:build` 无错误、无死链。

## 第三层:跨书检查(平台多本书之间)

- [ ] **术语统一**:同一概念在所有书里叫同一个名字(如"登录态/JWT/令牌"选定一个主叫法)?
- [ ] **不越界**:MVP 书里讲了属于平台书的内容(方法论、DDD、总架构)?上移到平台书,本地放链接。
- [ ] **互链有效**:本书指向其他 MVP 书/平台书的链接可达?
- [ ] **接口一致**:本书描述的对外接口(API/事件),与对方书里的描述一致?(以代码为准,两边都改)

## 收尾动作

- [ ] 修订完成后通读一遍**只看结论句**,做最后的一分钟复述测试;
- [ ] `git tag v1.0` 并在 README 标注"已完成 RC";
- [ ] 把本次发现的**共性问题**(比如总忘记写图说明)记到平台书的写作规范页,下一本书就不再犯。

> **节奏建议**:初稿(里程碑期间随码随写)→ 冷却 ≥2 天 → AI 初审(逐章挑断点)→ 人终审(本清单)→ 修订 → v1.0。RC 是每本书的**正式里程碑**,不做完不算交付。
