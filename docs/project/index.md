# 实战篇

> **结论先行**:这一篇按依赖顺序(MVP-0 → 4)讲清每个模块怎么从想法变成能跑的代码。**承诺:只读这本书就能讲清整个平台**——真实代码嵌在正文里、"为什么"讲透、坑写明白;仓库链接只是给想往下挖的人。

## 先看一眼全局(再读各章就不迷路)

```
                     登录(JWT)        ┌──────────────┐  发布 UserLogin 事件
        ┌──────────────────────────▶ │ MVP-0 用户中心 │ ─────────────┐
        │                            └──────────────┘              ▼
 ┌─────────────┐   拉书/章节         ┌──────────────┐        ┌──────────────┐
 │ MVP-2 阅读   │ ──────────────────▶ │ MVP-1 书库    │        │   RabbitMQ   │
 │ App(Compose)│                     └──────────────┘        └──────┬───────┘
 │  Room 缓存  │   划词提问           ┌──────────────┐               │ 广播
 └─────────────┘ ──────────────────▶ │ MVP-4 AI     │        ┌──────▼───────┐
        │            进度上报(HTTP)   │  (RAG 问答)  │        │ MVP-3 统计    │
        └──────────────────────────▶ └──────────────┘        └──────────────┘
```

读的顺序就是依赖的顺序:先有**门卫**(0),再有**内容**(1),然后**客户端**把它们串起来(2),行为产生**事件与统计**(3),最后 **AI** 让阅读变聪明(4)。

::: tip 这一篇的承诺:读完就懂,不用翻代码
每一章都把**真实代码片段嵌进正文**、把"为什么这么做"和"踩过的坑"讲透。想往下挖,再点章末「本章的真实代码」去对应仓库。各 MVP 的代码物理上在各自仓库(独立可部署),但**理解平台只需读这一本书**。
:::

:::
