# BookRealm v2 需求与执行计划

> **结论先行**:v2 不做“大而全阅读商业平台”,先做一个更像真实阅读 App 的版本。优先级是:阅读体验 → 笔记互动 → 听书 → 导入书籍 → 控制台。推荐、会员、小游戏和跨平台客户端先进入 v2.x 备选池。参考项目和 TTS 服务设计分别见 [v2 参考项目](/platform/reference-projects) 与 [br-tts-service 计划](/platform/tts-service-plan)。

## 一、v2 一分钟说明

BookRealm v2 要让读者从“能读一本书”升级到“愿意持续读一本书”:

读者能在更舒服的阅读器里看书、划线、写想法、查看目录;可以朗读当前章节;可以把 PDF/EPUB 导入书库;管理员能在控制台看到书、用户、阅读和 AI 使用情况。

这句话能说清,v2 才没有散。

## 二、v2 先做什么

**结论:先补阅读 App 的核心体验,再补内容生产和运营能力。**

| 顺序 | 能力 | 为什么先做 | 完成定义 |
| --- | --- | --- | --- |
| 1 | 阅读器 UI 与使用体验 | 用户每天看到的是阅读器,不是架构图 | 目录、进度条、主题、字号、行距、最近阅读、首页书架都可用 |
| 2 | 划线与段落笔记 | 微信读书式体验的核心不是“好看”,而是读者能留下想法 | 能对段落划线、评论、查看本书笔记列表 |
| 3 | 朗读/TTS | 读书 App 很自然会延伸到听书,也是移动端能力亮点 | App 可朗读章节,支持播放/暂停/进度;本地 TTS 保底,服务端 Qwen3-TTS 做高质量音频 |
| 4 | 管理控制台 | 现在我们自己也“看不到 App 怎么样”,需要可观测入口 | Web 控制台能看用户、书籍、阅读进度、AI 调用、错误 |
| 5 | PDF/EPUB 导入 | 平台不能只靠种子书,需要把外部书变成自己的结构化内容 | 上传 EPUB/PDF,抽取章节/段落,进入书库;PDF 先支持文字型,扫描 OCR 放后面 |

## 三、v2 暂时不做什么

**结论:不是这些功能不好,而是现在做会稀释主线。**

| 功能 | 暂缓原因 | 放到哪里 |
| --- | --- | --- |
| 支付/会员 | 没有真实商业闭环,做成“假支付”价值有限 | v2.x Demo 功能 |
| 大规模推荐算法 | 需要足够行为数据,否则只是列表排序 | v3 推荐系统 |
| 朋友圈/社区广场 | 会引入审核、关系链、通知、反作弊 | v3 社区 |
| 小说站抓取 | 版权和稳定性风险高 | 只做公版书/用户自有文件 |
| 文字游戏/小游戏 | 很有趣,但不是阅读 App 第一矛盾 | v2.x 实验室 |
| PC 客户端 | 成本高,与 Web 控制台重叠 | 先做 Web 管理台,再考虑桌面端 |
| vivo 灵动岛/系统级组件 | 依赖厂商能力,不适合第一批主线 | TTS 稳定后再做通知栏/小组件 |

## 四、v2 功能拆分

### 1. 阅读体验

**结论:先把阅读器变成“能长期使用”的界面。**

必须做:

- 首页显示最近阅读、书架、继续阅读入口;
- 书籍详情页有目录、简介、阅读状态;
- 阅读页支持目录抽屉、进度条、上一章/下一章;
- 支持主题、字号、行距;
- 支持横排/竖排阅读模式切换,古书、诗词、文言文优先适配竖排;
- 支持分页/连续滚动两种阅读方式;
- 阅读进度在本地和后端都可恢复;
- 空状态、加载状态、错误状态要像正式 App。

不急做:

- 复杂翻页动画;
- 高级排版引擎;
- 书城运营 Banner。

### 2. 划线、笔记、段评

**结论:笔记系统是 v2 最值得做的后端功能,因为它能让“段落”这个数据模型真正发挥价值。**

数据模型建议:

| 实体 | 核心字段 |
| --- | --- |
| Highlight | userId, bookId, chapterId, paragraphId, rangeStart, rangeEnd, color |
| Note | userId, paragraphId, content, visibility |
| NoteReply | noteId, userId, content |
| NoteLike | noteId, userId |

第一版只做:

- 对段落划线;
- 给段落写评论/想法;
- 查看本书全部笔记;
- 给笔记点赞。
- 选中词后弹出词典释义,再提供 AI 解释入口。

先不做:

- 复杂评论楼中楼;
- 全站热门评论;
- 敏感词审核系统。

### 3. 朗读/TTS

**结论:朗读先走本地高稳定方案,同时把服务端 TTS 设计成独立 MVP。**

第一阶段:

- Android 使用系统 TextToSpeech;
- 阅读页增加播放/暂停/停止;
- 当前朗读段落高亮;
- 朗读时自动滚动或翻页,形成跟读体验;
- 通知栏显示播放状态。

第二阶段:

- 后端新建 `br-tts-service`;
- 支持把章节文本生成音频文件;
- 缓存音频,避免重复调用模型;
- 可替换不同语音提供商。

不建议把 Qwen3-TTS 直接塞进 App 或 `br-ai-service`。已有 `tts pre` 更适合改造成 Python Worker;Spring Boot 负责任务、缓存、鉴权和音频文件管理。

### 4. 管理控制台

**结论:控制台不是给用户看的,是给我们看系统是否真实工作的。**

最小控制台:

- 用户列表、登录次数;
- 书籍列表、章节/段落数量;
- 阅读进度统计;
- AI 调用次数、失败次数、平均耗时;
- 最近错误日志。

技术建议:

- 先在用户中心现有 Web 能力上扩展一个 Admin 控制台;
- 或新建 `br-admin-web`,用 React + Ant Design 接各服务 API;
- 不建议把阅读 Web 和管理 Web 混在一起。

### 5. EPUB/PDF 导入

**结论:先做 EPUB,再做文字型 PDF,最后才做扫描 OCR。**

原因:

- EPUB 天生有章节结构,最容易变成 Book/Chapter/Paragraph;
- 文字型 PDF 可以抽文本,但章节识别不稳定;
- 扫描 PDF 需要 OCR、版面分析和人工校正,成本最高。

第一版接口:

| 接口 | 用途 |
| --- | --- |
| `POST /api/import/epub` | 上传 EPUB,解析成书籍 |
| `POST /api/import/pdf` | 上传文字型 PDF,抽取文本 |
| `GET /api/import/tasks/{id}` | 查看导入状态 |
| `POST /api/books/{id}/publish` | 管理员确认后发布到书库 |

## 五、推荐怎么做

**结论:推荐先做“可解释规则”,不要一上来追大厂算法。**

v2 可做轻推荐:

- 最近阅读;
- 同标签书籍;
- 读过同一本书的人还读了什么;
- AI 根据当前书生成“下一本推荐理由”。

马斯克 X 推荐算法、深度召回、多路排序这些可以学习,但需要行为数据和实验平台。现在直接上会变成“名字很大,效果看不见”。

## 六、建议新仓库

**结论:v2 不一定立刻建很多仓,但要先定边界。**

| 仓库/模块 | 建议 | 理由 |
| --- | --- | --- |
| br-reader-app | 继续主力开发 | v2 大部分价值在 App 体验 |
| br-library-service | 增加导入能力,或拆出 import 模块 | EPUB/PDF 最终进入书库 |
| br-event-stats | 增加 AI 使用统计和阅读时长 | 控制台需要数据 |
| br-ai-service | 保留摘要/问答,预留 TTS | 不要把所有新能力塞进 AI |
| br-tts-service | v2.3 新建 | 服务端 Qwen3-TTS 朗读、任务队列、音频缓存 |
| br-admin-web | v2 中后期新建 | 专门做控制台 |
| br-social-service | 暂缓 | 笔记可先放阅读/书库相关服务,社区化以后再拆 |

## 七、v2 里程碑

### v2.1 阅读器成型

完成:

- 首页最近阅读/继续阅读;
- 阅读页目录、进度、主题、字号、行距;
- App 空/错/加载状态整理;
- 平台书补“阅读体验实战章”。

### v2.2 笔记系统

完成:

- 后端 API:划线、笔记、点赞;
- App:段落菜单、笔记列表;
- 数据库迁移和测试;
- 平台书补“笔记与互动实战章”。

### v2.3 朗读

完成:

- Android 本地 TTS 播放;
- 当前段落高亮;
- 通知栏播放控制;
- 后端预留 TTS 设计文档。

### v2.4 控制台

完成:

- Web Admin 可登录;
- 能看用户、书、阅读、AI、错误;
- 写“可观测性与管理台”章节。

### v2.5 导入书籍

完成:

- EPUB 导入;
- 文字型 PDF 导入;
- 管理员确认发布;
- AI 可对导入书籍 embed 和问答。

## 八、下一步行动

**结论:现在不要先做推荐和支付,先做 v2.1。**

第一张工单应该是:

> 完善 Android 阅读体验:首页最近阅读、阅读器目录/进度/主题/字号/行距、空错加载状态,并更新平台书。

这一步做完,BookRealm 会从“能演示”变成“像一个真的阅读 App”。后面的划线、朗读、导入和控制台才有更稳的承载面。
