# P6 动态建模

> **结论先行**:登录事件流、打开一本书、AI 问答的顺序图/活动图。

## 一句话结论

**三条核心交互路径覆盖平台所有 BC——登录事件流横跨用户/App/统计三个 BC,打开书阅读横跨 App/书库两个 BC,AI 问答横跨 App/AI 两个 BC——每条路径的参与者和消息都与 P5 的 BC 划分一致,箭头上标明传的是什么。**

## 图一:登录事件流

App → 用户中心 → RabbitMQ → 日志服务 + 统计服务

```
  阅读App(MVP-2)          用户中心(MVP-0)       RabbitMQ         日志服务(MVP-3)     统计服务(MVP-3)
       │                      │                    │                    │                    │
       │ ① POST /api/auth/   │                    │                    │                    │
       │    login             │                    │                    │                    │
       │ (username,password)  │                    │                    │                    │
       │─────────────────────>│                    │                    │                    │
       │                      │                    │                    │                    │
       │                      │ ② 校验凭据         │                    │                    │
       │                      │    生成 JWT         │                    │                    │
       │                      │                    │                    │                    │
       │                      │ ③ 发布 UserLogin   │                    │                    │
       │                      │    事件             │                    │                    │
       │                      │───────────────────>│                    │                    │
       │                      │                    │                    │                    │
       │ ④ 返回 JWT          │                    │ ⑤ fanout           │                    │
       │<─────────────────────│                    │──┬─────────────────>│                    │
       │                      │                    │  │                  │                    │
       │ ⑥ 存入 DataStore     │                    │  │                  │ ⑦ 消费事件         │
       │    跳转书架页         │                    │  │                  │    更新 LoginStats  │
       │                      │                    │  │                  │<───────────────────│
       │                      │                    │  │                  │                    │
       │                      │                    │  └──────────────────│──────────────────>│
       │                      │                    │                     │ ⑧ 消费事件         │
       │                      │                    │                     │    写 LoginLog      │
```

**金字塔说明**:
- **结论**:一次登录触发两条异步链路——统计服务实时聚合登录次数,日志服务持久化登录记录——登录体验不受后台处理影响。
- **根据**:用户中心同步返回 JWT(④),事件发布和消费完全异步(⑤⑥⑦⑧),读者不需要等统计落盘就能进入书架。
- **例子**:读者输入账号密码点登录,不到半秒就跳转书架页(④→⑥),与此同时统计库的"今日登录次数"悄悄 +1(⑦),日志文件多了一行记录(⑧)。

## 图二:打开一本书并阅读

App → 书库服务 → Room(本地缓存)

```
  阅读App(MVP-2)                        书库服务(MVP-1)                  Room(本地)
       │                                      │                              │
       │ ① GET /api/books/{id}/chapters      │                              │
       │─────────────────────────────────────>│                              │
       │                                      │                              │
       │ ② 返回章节目录 JSON                  │                              │
       │<─────────────────────────────────────│                              │
       │                                      │                              │
       │ ③ 展示章节目录                       │                              │
       │    读者点击某章                       │                              │
       │                                      │                              │
       │ ④ 先查 Room:该章缓存?                │                              │
       │────────────────────────────────────────────────────────────────────>│
       │                                      │                              │
       │    alt [缓存命中且未过期]              │                              │
       │ ⑤ 返回缓存章节内容                   │                              │
       │<────────────────────────────────────────────────────────────────────│
       │                                      │                              │
       │    alt [缓存未命中]                   │                              │
       │ ⑥ GET /api/chapters/{id}            │                              │
       │─────────────────────────────────────>│                              │
       │                                      │                              │
       │ ⑦ 返回章节内容(含段落结构)           │                              │
       │<─────────────────────────────────────│                              │
       │                                      │                              │
       │ ⑧ 存 Room 缓存                       │                              │
       │────────────────────────────────────────────────────────────────────>│
       │                                      │                              │
       │ ⑨ 阅读器渲染章节                     │                              │
       │    读者翻页阅读                       │                              │
       │                                      │                              │
       │ ⑩ 每翻一页:更新 ReadingProgress      │                              │
       │────────────────────────────────────────────────────────────────────>│
       │                                      │                              │
       │ ⑪ 退出阅读器                         │                              │
       │    上报 ReadingProgress 事件          │                              │
       │──→(经书库服务或直连 RabbitMQ,见 P5 待定)                             │
```

**金字塔说明**:
- **结论**:打开一本书走"先网络后本地"两阶段——首次加载从书库 API 拉取并写入 Room 缓存,后续打开直接读缓存,离线也可阅读。
- **根据**:Room 作为本地缓存层(④⑤),网络不可达时(如地铁隧道)读者仍能读已缓存章节;进度存在本地(⑩),退出时异步上报(⑪),不阻塞翻页。
- **例子**:读者在家连 WiFi 打开《西游记》第一章(⑥→⑦→⑧),地铁上继续读第二章时 App 先查 Room 命中缓存(⑤),零网络请求,翻页流畅。

## 图三:AI 读书问答

App → AI 服务 → 向量库 → LLM

```
  阅读App(MVP-2)          AI服务(MVP-4)          向量库               LLM(DeepSeek)
       │                      │                    │                    │
       │ ① 读者选中一段文字    │                    │                    │
       │    点击"问问AI"       │                    │                    │
       │                      │                    │                    │
       │ ② POST /api/ai/ask  │                    │                    │
       │   {selectedText,     │                    │                    │
       │    chapterId,        │                    │                    │
       │    question}         │                    │                    │
       │─────────────────────>│                    │                    │
       │                      │                    │                    │
       │                      │ ③ 将问题向量化     │                    │
       │                      │                    │                    │
       │                      │ ④ 向量检索         │                    │
       │                      │   (按 chapterId    │                    │
       │                      │    限定范围)       │                    │
       │                      │───────────────────>│                    │
       │                      │                    │                    │
       │                      │ ⑤ 返回 Top-K       │                    │
       │                      │    相关段落         │                    │
       │                      │<───────────────────│                    │
       │                      │                    │                    │
       │                      │ ⑥ 组装 prompt:     │                    │
       │                      │   [相关段落]        │                    │
       │                      │   + [选中文本]      │                    │
       │                      │   + [问题]          │                    │
       │                      │                    │                    │
       │                      │ ⑦ 发送 prompt      │                    │
       │                      │────────────────────────────────────────>│
       │                      │                    │                    │
       │                      │ ⑧ 返回回答          │                    │
       │                      │   (含原文引用)       │                    │
       │                      │<────────────────────────────────────────│
       │                      │                    │                    │
       │ ⑨ 返回{answer,       │                    │                    │
       │    citations}        │                    │                    │
       │<─────────────────────│                    │                    │
       │                      │                    │                    │
       │ ⑩ 阅读器底部弹出       │                    │                    │
       │    问答面板           │                    │                    │
       │    (显示回答+原文引用) │                    │                    │
```

**金字塔说明**:
- **结论**:AI 问答的关键在于"限定范围检索"——提问时带上章节 ID,向量检索只在当前章节范围内查找,回答带上原文引用,避免 LLM 凭空编造。
- **根据**:向量检索限定范围(④按 chapterId 过滤)+ 原文引用(⑧)两道关卡确保回答可信;检索在毫秒级完成,LLM 调用是主要耗时。
- **例子**:读者读到"悟空道:师父,我晓得了"时划词问"悟空当时懂了什么",AI 从本章向量库中检索悟空与菩提祖师的前后对话(④⑤),LLM 基于检索到的上下文回答(⑦⑧),并在回答中标注"出自本章第 X 段"(⑨⑩)。

## 附一:阅读进度状态机(状态图)

**阅读进度在不同状态间流转,每个状态由不同 BC 持有**:

```
        ┌──────────────┐
        │  未开始阅读   │  ← 书架上某本书从未被打开
        └──────┬───────┘
               │ 读者点击章节进入阅读器
               ▼
        ┌──────────────┐
        │   正在阅读    │  ← 阅读器中,每次翻页更新本地进度
        └──────┬───────┘
               │ 退出阅读器 / App 退到后台
               ▼
        ┌──────────────┐
        │  进度已保存   │  ← Room 存 currentParagraph + 时间戳
        └──────┬───────┘
               │ 再次打开该书
               ▼
        ┌──────────────┐
        │  恢复到原位   │  ← 阅读器跳转到上次保存的段落
        └──────┬───────┘
               │ 上报 ReadingProgress 事件(异步)
               ▼
        ┌──────────────┐
        │  服务端记录   │  ← 统计 BC 消费事件,更新 ReadingStats
        └──────────────┘

触发事件:
  打开书 → "未开始"→"正在阅读"
  翻页   → 更新进度(仍在"正在阅读")
  退出   → "正在阅读"→"进度已保存"
  重返   → "进度已保存"→"恢复到原位"→回到"正在阅读"
  同步   → "进度已保存"→"服务端记录"(异步,不影响本地状态)
```
