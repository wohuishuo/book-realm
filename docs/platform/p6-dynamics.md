# P6 动态建模

> **结论先行**:三条核心交互路径——登录事件流、打开书阅读、AI 问答——覆盖所有 BC。每个参与者来自 P5 的 BC 划分,箭头上标明传什么。

## 图一:登录事件流

```
  阅读App(MVP-2)          用户中心(MVP-0)       RabbitMQ         日志服务(MVP-3)     统计服务(MVP-3)
       │                      │                    │                    │                    │
       │ ① POST /api/auth/   │                    │                    │                    │
       │    login             │                    │                    │                    │
       │─────────────────────>│                    │                    │                    │
       │                      │ ② 校验 + 发 JWT    │                    │                    │
       │                      │ ③ 发布 UserLogin   │                    │                    │
       │                      │───────────────────>│                    │                    │
       │ ④ 返回 JWT          │                    │ ⑤ fanout           │                    │
       │<─────────────────────│                    │──┬─────────────────>│                    │
       │                      │                    │  │                  │ ⑥ 更新 LoginStats  │
       │ ⑦ 存 DataStore      │                    │  └──────────────────│──────────────────>│
       │    跳转书架           │                    │                     │ ⑧ 写 LoginLog      │
```

**结论:一次登录触发两条异步链路,同步只返回 JWT,登录体验不受后台处理影响。**

**根据**:用户中心在④返回 JWT 后登录即完成;③~⑧全部异步,读者不需等统计落盘。RabbitMQ fanout 保证两个消费者各自独立消费,互不阻塞。

**例子**:读者点登录,半秒内跳转书架。同时统计库"今日登录次数"悄悄 +1,日志文件多一行记录——这些后台动作读者完全无感。

## 图二:打开一本书并阅读

```
  阅读App(MVP-2)                        书库服务(MVP-1)                  Room(本地)
       │                                      │                              │
       │ ① GET /api/books/{id}/chapters      │                              │
       │─────────────────────────────────────>│                              │
       │ ② 返回章节目录                       │                              │
       │<─────────────────────────────────────│                              │
       │ ③ 读者点击某章 → 查 Room             │                              │
       │────────────────────────────────────────────────────────────────────>│
       │    alt [命中:④ 返回缓存]              │                              │
       │<────────────────────────────────────────────────────────────────────│
       │    alt [未中:⑤ GET /api/chapters/{id}]│                              │
       │─────────────────────────────────────>│                              │
       │ ⑥ 返回章节(段落结构)                 │                              │
       │<─────────────────────────────────────│                              │
       │ ⑦ 写 Room 缓存                       │                              │
       │────────────────────────────────────────────────────────────────────>│
       │ ⑧ 阅读器渲染,翻页 → 更新本地进度      │                              │
       │ ⑨ 退出 → 上报 ReadingProgress 事件   │                              │
```

**结论:首次在线加载后写 Room 缓存,后续直接读缓存,离线也能阅读。**

**根据**:Room 作为本地缓存层,网络不可达时读缓存(④)。进度存在本地(⑧),退出时异步上报(⑨),不阻塞翻页。

**例子**:在家 WiFi 打开《西游记》第一章,网络加载并缓存(⑤~⑦)。地铁上续读同一章,直接命中 Room 缓存,零网络请求,翻页零延迟。

## 图三:AI 读书问答

```
  阅读App(MVP-2)          AI服务(MVP-4)          向量库               LLM(DeepSeek)
       │                      │                    │                    │
       │ ① 长按选中 + 提问     │                    │                    │
       │ ② POST /api/ai/ask  │                    │                    │
       │   {selectedText,     │                    │                    │
       │    chapterId,        │                    │                    │
       │    question}         │                    │                    │
       │─────────────────────>│                    │                    │
       │                      │ ③ 问题向量化       │                    │
       │                      │ ④ 检索(限定 chapterId)                  │
       │                      │───────────────────>│                    │
       │                      │ ⑤ 返回 Top-K 段落  │                    │
       │                      │<───────────────────│                    │
       │                      │ ⑥ 组 prompt + 发 LLM                    │
       │                      │────────────────────────────────────────>│
       │                      │ ⑦ 回答(含原文引用)  │                    │
       │                      │<────────────────────────────────────────│
       │ ⑧ 返回{answer,       │                    │                    │
       │    citations}        │                    │                    │
       │<─────────────────────│                    │                    │
       │ ⑨ 阅读器底部面板      │                    │                    │
       │    显示回答 + 出处    │                    │                    │
```

**结论:关键在"限定范围检索"——带上章节 ID,向量检索只查当前章节,回答附原文引用,LLM 不会凭空编造。**

**根据**:④按 chapterId 过滤 + ⑦原文引用两道关卡。检索毫秒级,LLM 调用是主要耗时。降级策略:向量库未覆盖时仅用选中文本+问题发 LLM。

**例子**:读到"悟空道:师父,我晓得了",划词问"悟空懂了什么"。AI 从本章向量库检索菩提祖师前后对话,回答"悟空悟透了打他三下的暗语"并标注出自本章第 X 段。
