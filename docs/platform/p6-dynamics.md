# P6 动态建模

> **结论先行**:三条核心交互路径覆盖所有 BC——登录事件流跨用户/App/统计,打开书阅读跨 App/书库,AI 问答跨 App/AI。每个参与者都来自 P5 的 BC 划分,箭头上标明传什么。

## 图一:登录事件流

```
  阅读App(MVP-2)          用户中心(MVP-0)       RabbitMQ         日志服务(MVP-3)     统计服务(MVP-3)
       │                      │                    │                    │                    │
       │ ① POST /api/auth/   │                    │                    │                    │
       │    login             │                    │                    │                    │
       │─────────────────────>│                    │                    │                    │
       │                      │ ② 校验凭据         │                    │                    │
       │                      │    生成 JWT         │                    │                    │
       │                      │ ③ 发布 UserLogin   │                    │                    │
       │                      │───────────────────>│                    │                    │
       │ ④ 返回 JWT          │                    │ ⑤ fanout           │                    │
       │<─────────────────────│                    │──┬─────────────────>│                    │
       │                      │                    │  │                  │                    │
       │ ⑥ 存入 DataStore     │                    │  │                  │ ⑦ 消费事件         │
       │    跳转书架页         │                    │  │                  │    更新 LoginStats  │
       │                      │                    │  └──────────────────│──────────────────>│
       │                      │                    │                     │ ⑧ 消费事件         │
       │                      │                    │                     │    写 LoginLog      │
```

- **结论**:一次登录触发两条异步链路——统计实时聚合,日志持久化——登录体验不受后台处理影响。
- **根据**:用户中心同步返回 JWT(④),事件异步消费(⑤~⑧)。读者不需等统计落盘就能进书架。
- **例子**:读者输入密码点登录,不到半秒跳转书架,同时统计库"今日登录次数"悄悄 +1,日志多一行记录。

## 图二:打开一本书并阅读

```
  阅读App(MVP-2)                        书库服务(MVP-1)                  Room(本地)
       │                                      │                              │
       │ ① GET /api/books/{id}/chapters      │                              │
       │─────────────────────────────────────>│                              │
       │ ② 返回章节目录 JSON                  │                              │
       │<─────────────────────────────────────│                              │
       │ ③ 展示章节目录,读者点击某章           │                              │
       │                                      │                              │
       │ ④ 先查 Room:该章缓存?                │                              │
       │────────────────────────────────────────────────────────────────────>│
       │    alt [命中] → ⑤ 返回缓存内容       │                              │
       │<────────────────────────────────────────────────────────────────────│
       │    alt [未中]                         │                              │
       │ ⑥ GET /api/chapters/{id}            │                              │
       │─────────────────────────────────────>│                              │
       │ ⑦ 返回章节(含段落结构)               │                              │
       │<─────────────────────────────────────│                              │
       │ ⑧ 存 Room 缓存                       │                              │
       │────────────────────────────────────────────────────────────────────>│
       │                                      │                              │
       │ ⑨ 阅读器渲染,读者翻页                │                              │
       │ ⑩ 每翻一页:更新 ReadingProgress      │                              │
       │────────────────────────────────────────────────────────────────────>│
       │ ⑪ 退出 → 上报 ReadingProgress 事件   │                              │
```

- **结论**:打开书走"先网络后本地"——首次从 API 拉取并写 Room 缓存,后续直接读缓存,离线也能读。
- **根据**:Room 作为本地缓存层(④⑤),网络不可达时读缓存;进度存本地(⑩),退出异步上报(⑪)。
- **例子**:在家 WiFi 打开《西游记》第一章加载后入缓存(⑥~⑧),地铁上续读直接在 Room 命中,零网络请求。

## 图三:AI 读书问答

```
  阅读App(MVP-2)          AI服务(MVP-4)          向量库               LLM(DeepSeek)
       │                      │                    │                    │
       │ ① 长按选中文字        │                    │                    │
       │ ② POST /api/ai/ask  │                    │                    │
       │   {selectedText,     │                    │                    │
       │    chapterId,        │                    │                    │
       │    question}         │                    │                    │
       │─────────────────────>│                    │                    │
       │                      │ ③ 问题向量化       │                    │
       │                      │ ④ 向量检索(限定    │                    │
       │                      │    chapterId 范围)  │                    │
       │                      │───────────────────>│                    │
       │                      │ ⑤ 返回 Top-K 段落  │                    │
       │                      │<───────────────────│                    │
       │                      │ ⑥ 组装 prompt:     │                    │
       │                      │   [段落]+[选中]+[问]│                    │
       │                      │ ⑦ 发 LLM           │                    │
       │                      │────────────────────────────────────────>│
       │                      │ ⑧ 回答(含原文引用)  │                    │
       │                      │<────────────────────────────────────────│
       │ ⑨ 返回{answer,       │                    │                    │
       │    citations}        │                    │                    │
       │<─────────────────────│                    │                    │
       │ ⑩ 阅读器底部面板      │                    │                    │
       │    显示回答+引用      │                    │                    │
```

- **结论**:AI 问答关键是"限定范围检索"——带上章节 ID,向量检索只查当前章节,回答附原文引用,避免 LLM 编造。
- **根据**:向量检索限定章节范围(④) + 原文引用(⑧)两道关卡确保回答可信。
- **例子**:读到"悟空道:师父,我晓得了"划词问"悟空懂了什么",AI 检索本章菩提祖师前后对话,回答"悟空悟透了菩提祖师打他三下的暗语"并标注出处。

