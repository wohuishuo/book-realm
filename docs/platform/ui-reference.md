## 二、怎么处理一张图

**结论:每张图只回答三件事。**

```text
这张图解决什么问题:
BookRealm 要学什么:
BookRealm 不学什么:
```

例子:

```text
文件: 微信读书/书-阅读-选中了文字-划线菜单.jpg
这张图解决什么问题: 用户选中文字后,如何在不离开阅读页的情况下复制、划线、写想法、AI 问书、听当前内容。
BookRealm 要学什么: 选区菜单分两层,第一层是动作,第二层是高亮颜色和样式。
BookRealm 不学什么: 不直接复制图标、颜色和完整布局。
```

## 三、微信读书参考结论

**结论:微信读书最值得学的是“阅读器里的工具层”。**

| 参考图 | 解决的问题 | BookRealm 学什么 |
| --- | --- | --- |
| `微信读书/阅读.jpg` | 阅读页默认状态 | 阅读页应该干净,文字优先,工具默认隐藏 |
| `微信读书/书-阅读-点击屏幕-张开上下ui.jpg` | 点击屏幕后显示顶部/底部工具 | 顶部放返回、分享、更多;底部放目录、进度、亮度、字体 |
| `微信读书/书-阅读-下ui-目录.jpg` | 阅读页内打开目录 | 目录是抽屉或底板,不跳出阅读上下文 |
| `微信读书/书-阅读-下ui-字体.jpg` | 字号/排版设置 | 设置要即时预览,不要藏太深 |
| `微信读书/书-阅读-下ui-背景颜色.jpg` | 阅读主题 | 主题应是少量高质量预设,不是无限颜色盘 |
| `微信读书/书-阅读-选中了文字-划线菜单.jpg` | 选中文字后的操作 | 复制、划线、写想法、书摘、AI 问书、听当前 |
| `微信读书/书-阅读-中间ui泡泡-ai.jpg` | AI 入口 | AI 入口适合做浮动胶囊,但不能遮挡正文 |
| `微信读书/书-阅读-中间ui泡泡-听.jpg` | 听书入口 | 听书入口应和阅读上下文绑定 |
| `微信读书/书-详细-长图.jpg` | 书籍详情页 | 详情页要包含简介、书评、我的阅读、作者信息 |
| `微信读书/书架.jpg` | 书架首页 | 书架先服务“继续读”,再服务运营推荐 |

BookRealm v2.1 应优先吸收:

- 阅读页工具默认隐藏,点击正文唤起;
- 底部工具栏:目录、进度、主题、字体、AI、听书;
- 选中文字菜单:复制、划线、笔记、AI 解释、听当前;
- 书籍详情页分区:简介、目录、笔记/书评、作者/来源。

暂不吸收:

- 社交压力很强的排行榜和书友动态;
- 复杂会员/付费入口;
- 大量运营活动。

## 四、起点参考结论

**结论:起点最值得学的是“长篇小说平台的信息密度和段评气氛”。**

| 参考图 | 解决的问题 | BookRealm 学什么 |
| --- | --- | --- |
| `起点/书架.jpg` | 小说书架与最近更新 | 书架列表要显示进度、更新时间、未读章节 |
| `起点/书架-上ui-搜索-张开.jpg` | 书架搜索 | 搜索应贴近书架,不是只在书城 |
| `起点/书架-书详细-长图.jpg` | 商业小说详情页 | 详情页可承载目录、简介、作者、同类推荐、看点 |
| `起点/书架-书详细-目录.jpg` | 长篇目录 | 目录要支持大量章节、最新章节和跳转 |
| `起点/书架-立刻阅读-选中文字.jpg` | 阅读选区工具 | 段评、开始听、词典、标记、打赏、分享、配音这些动作可拆优先级 |
| `起点/书架-立刻阅读-点卡评论.jpg` | 段落评论 | 段评数量贴在段落旁,让读者知道哪里有人讨论 |
| `起点/书架-每日导读.jpg` | 阅读习惯/导读 | 首页可以有每日导读,但 v2 不做重运营 |
| `起点/我-我的阅历-长图.jpg` | 阅读成就 | 阅读统计和等级可以成为轻量激励 |

BookRealm v2.1/v2.2 应优先吸收:

- 书架显示“上次读到哪里”;
- 详情页有长页结构,但减少付费商业模块;
- 段落旁可以显示笔记/评论数量;
- 选区工具里保留“词典、AI、听、标记”。

暂不吸收:

- 充值、月票、会员、福利中心;
- 大量活动入口;
- 强商业化榜单;
- 卡牌广场和小游戏入口。

## 五、页面级设计决策

### 1. 书架页

**结论:书架页先做“继续阅读”,再做推荐。**

v2.1 书架应包含:

- 最近阅读卡片;
- 书架列表/网格切换;
- 搜索入口;
- 导入书籍入口;
- 每本书显示封面、书名、作者、阅读进度、上次阅读时间;
- 空书架状态。

不做:

- 充值/会员;
- 大型活动 Banner;
- 卡牌/游戏化入口。

### 2. 书籍详情页

**结论:详情页要帮助读者决定“现在读不读”,不是堆满运营模块。**

v2.1 详情页应包含:

- 封面、书名、作者、标签;
- 简介和展开;
- 目录入口;
- 阅读进度;
- 加入书架/继续阅读;
- 本书笔记数量;
- AI 摘要入口。

v2.2 再加:

- 书评/段评;
- 同类推荐;
- 作者页。

### 3. 阅读页

**结论:阅读页是 v2 的核心,必须先做舒服。**

v2.1 阅读页应包含:

- 点击正文显示顶部/底部工具;
- 顶部:返回、标题、分享/更多;
- 底部:目录、进度、主题、字体、AI、听书;
- 字号、行距、背景主题;
- 横排/竖排模式;
- 分页/连续滚动模式;
- 当前章进度;
- 下一章/上一章。

v2.2 再加:

- 选中文字菜单;
- 高亮颜色;
- 写想法;
- 词典解释;
- 段评数量。

### 4. 听书页/浮层

**结论:听书不是单独播放器,而是阅读页的另一种状态。**

v2.3 听书应包含:

- 播放/暂停;
- 上一段/下一段;
- 15 秒前进/后退;
- 语速;
- 音色;
- 定时关闭;
- 当前段落高亮;
- 通知栏控制。

服务端 Qwen3-TTS 生成慢,所以 App 要支持“生成中”状态,不能卡死阅读。

### 5. 选区菜单

**结论:选区菜单要短,不能把所有功能都塞第一层。**

第一层:

- 复制;
- 划线;
- 写想法;
- AI 解释;
- 听当前;
- 词典。

第二层:

- 高亮颜色;
- 删除划线;
- 分享;
- 书摘。

## 六、v2.1 工单裁剪

**结论:下一轮不要直接做全部 UI,先做阅读主链路的 6 个组件。**

v2.1 必做:

1. 书架页:最近阅读 + 书架列表;
2. 详情页:简介 + 目录 + 继续阅读;
3. 阅读页工具层:点击显示顶部/底部 UI;
4. 阅读设置:字号、行距、主题;
5. 阅读导航:目录、进度、上一章/下一章;
6. 空/错/加载状态。

v2.2 再做:

1. 选区菜单;
2. 划线和笔记;
3. 段评数量;
4. 词典入口;
5. AI 解释入口优化。

v2.3 再做:

1. 本地 TTS;
2. 服务端 TTS 任务;
3. 听书浮层;
4. 当前段落跟读。
