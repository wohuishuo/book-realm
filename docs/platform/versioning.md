# 版本规则:产品版本和工程阶段分开

> **结论先行**:BookRealm 以后同时使用两套编号。产品版本写给用户、老师和 GitHub Release;工程阶段写给开发者排工单。`v2.1/v2.2` 不是 App 成熟度,只是内部路线。

## 一、当前版本

**当前 App 产品版本是 `0.3.0-alpha.20260616`。**

它的意思是:

| 部分 | 含义 |
| --- | --- |
| `0.3.0` | 已进入阅读互动阶段:登录、书架、阅读、AI、划线、笔记、段评、点赞主要链路已经接入 |
| `alpha` | 功能能跑,但 UI 手感、信息架构、我的页和自动化验收还不够稳 |
| `20260616` | 里程碑日期,方便从版本名知道是哪一批构建 |

所以它不是 `1.0`。我们不能因为内部做到了 v2.x 工单,就把 App 说成成熟产品。

## 二、两套编号怎么用

| 编号 | 给谁看 | 放在哪里 | 例子 |
| --- | --- | --- | --- |
| 产品版本 | 使用者、老师、Release 页面 | Android `versionName`、README、发布说明 | `0.3.0-alpha.20260616` |
| 工程阶段 | 开发者、平台书、TODO | 平台书、工单、进度文件 | `v2.2 笔记互动` |

产品版本回答“这个 App 有多成熟”。工程阶段回答“我们正在做哪类能力”。

## 三、产品版本路线

| 版本 | 状态 | 完成定义 |
| --- | --- | --- |
| `0.1.0-alpha` | 最小闭环 | 登录、搜书、详情、阅读、书架 |
| `0.2.0-alpha` | AI 与统计 | 阅读进度上报、AI 摘要、AI 原文问答 |
| `0.3.0-alpha` | 阅读互动 | 划线、笔记、段评、点赞进入 App |
| `0.4.0-beta` | 阅读产品化 | 书架/书城逻辑清楚,阅读设置记忆,划线可编辑删除,我的笔记可用,真机 UI 自动验收成型 |
| `0.5.0-beta` | AI 记忆 | AI 对话历史、按书/章节/段落沉淀为个人记录 |
| `0.6.0-alpha` | 朗读 MVP | 本地 TTS、播放控制、当前段落高亮 |
| `1.0.0` | 可交付版本 | 普通读者不用说明书也能完成主要阅读链路,主要功能有自动化测试兜底 |

## 四、1.0 不是什么

**结论:1.0 不是功能最多,而是主链路可信。**

1.0 至少要满足:

- 书架搜索只搜自己的书,书城搜索搜全站书;
- 书能加入和移出书架;
- 阅读设置能记忆主题、字号、行距;
- 已划线点击后能改颜色、写笔记、删除;
- 段评有独立视觉,不是和划线混成一种效果;
- 我的页能打开阅读统计、我的笔记、我的段评;
- AI 问答有历史记录;
- 登录、搜索、阅读、划线、笔记、段评、AI、返回逻辑有自动化验收。

这也是下一阶段 `0.4.0-beta` 的方向。

## 五、工程阶段仍然保留

平台书里的 `v2.1/v2.2/v2.3` 不删除,因为它们是历史和路线:

- `v2.1`:阅读体验骨架;
- `v2.2`:划线、笔记、段评、AI 解释;
- `v2.3`:朗读/TTS;
- `v2.4+`:控制台、导入、推荐等扩展。

但在 App、README 和 GitHub Release 里,优先使用产品版本,避免“看起来都 2.2 了为什么还粗糙”的误解。
