# P3 功能分解树

> **结论先行**:平台功能层次树,每个 MVP 一棵子树,明确做什么不做什么。

## 一句话结论

**书域平台 = 五个独立 MVP 的功能合集,每个 MVP 独立可运行;砍单顺序为 AI 服务 → 阅读进度事件 → 书城搜索,核心主线(用户中心 + 书库 + App 基础 + 登录事件)是底线。**

## 功能树

```
书域平台(电子书 + AI 问答)
│
├─ MVP-0 用户中心(认证服务)
│   ├─ 注册(用户名/密码)
│   ├─ 登录(返回 JWT)
│   ├─ Token 校验(拦截器)
│   └─ 发布 UserLogin 事件(RabbitMQ 生产者)
│   【边界】只做认证,不做用户资料/头像/社交;复用已完成的 user-center 仓
│
├─ MVP-1 书库服务(内容 API)
│   ├─ 书籍管理
│   │   ├─ 书籍 CRUD(管理员上传/编辑/下架)
│   │   └─ 封面文件存储
│   ├─ 章节管理
│   │   ├─ 章节列表(按书查询)
│   │   ├─ 章节内容(段落结构)
│   │   └─ 章节文本存取
│   ├─ 内容搜索
│   │   ├─ 按书名/作者搜索
│   │   └─ 按标签过滤
│   └─ 种子数据(公版书预置)
│   【边界】只提供 REST API,不含前端页面;不承担推荐算法
│
├─ MVP-2 阅读 App(Android Compose)
│   ├─ 登录与认证
│   │   ├─ 登录页(对接用户中心 JWT)
│   │   └─ Token 持久化(DataStore)
│   ├─ 书架
│   │   ├─ 我的书架(已收藏的书)
│   │   ├─ 最近阅读(进度卡片)
│   │   └─ 离线缓存(Room 同步书库数据)
│   ├─ 书城
│   │   ├─ 书籍列表(搜索/浏览)
│   │   └─ 书籍详情(简介 + 章节目录)
│   ├─ 阅读器
│   │   ├─ 章节渲染(分页 + 翻页动画)
│   │   ├─ 阅读进度记忆(退出重进回到原位)
│   │   ├─ 字号/主题调节
│   │   ├─ 划词 AI 问答(选中文本 → 弹出问答面板)
│   │   └─ 上报 ReadingProgress 事件
│   └─ 导航骨架(Hilt + Navigation + 主题)
│   【边界】只做阅读客户端,不内置书评/社交/书单功能
│
├─ MVP-3 事件驱动统计(RabbitMQ + 两个微服务)
│   ├─ 事件基础设施
│   │   ├─ RabbitMQ 消息队列
│   │   └─ UserLogin / ReadingProgress 事件定义
│   ├─ 日志服务
│   │   ├─ 消费 UserLogin 事件
│   │   └─ 登录记录落盘
│   ├─ 统计服务
│   │   ├─ 消费 UserLogin 事件(登录次数/类型统计)
│   │   └─ 消费 ReadingProgress 事件(阅读章节数聚合)
│   └─ 统计查询 API
│       ├─ 查询"手机登录 X 次"
│       └─ 查询"读了多少章"
│   【边界】只做事件消费与统计,不做实时看板/大数据分析
│
├─ MVP-4 AI 服务(Spring AI + RAG)
│   ├─ 书籍向量化
│   │   ├─ 章节文本分段
│   │   └─ 向量库入库
│   ├─ RAG 读书问答
│   │   ├─ 接收划词提问(含上下文章节 ID)
│   │   ├─ 向量检索相关段落
│   │   └─ LLM 生成带原文引用的回答
│   └─ 章节摘要
│       └─ 给定章节文本返回摘要
│   【边界】只做文本理解,不做 AI 续写/角色扮演/推荐
│
└─ MVP-5 书友匹配(可选,时间不够第一个砍)
    ├─ 标签匹配(按喜欢的书的标签匹配书友)
    └─ Redis 缓存预热
    【边界】MVP 阶段不启动,仅保留设计占位
```

## 砍单顺序

按依赖和重要程度,时间不够时按序砍掉(每砍一个平台其余仍完整):

| 砍单序号 | 砍掉的功能 | 触发条件 | 后果 |
| --- | --- | --- | --- |
| 1 | MVP-5 书友匹配 | P 阶段结束后即搁置 | 无影响,它本来就是可选的 |
| 2 | MVP-4 AI 摘要(保留 RAG 问答) | 第 4 周 AI 服务进度滞后 | RAG 问答仍是亮点,摘要可降级为"占位按钮" |
| 3 | MVP-3 阅读进度事件(保留登录事件) | 第 4 周统计服务进度滞后 | 登录事件已满足训练课题要求 |
| 4 | MVP-2 书城搜索(保留书架+阅读器) | 第 3 周 App 进度滞后 | 可通过"最近阅读"和直接输入书名找到书 |

**底线(不可砍)**:用户中心认证 + 书库 API + App 书架与阅读器主线 + 登录事件——这四样构成了"能登录、能读书、能统计"的最小闭环,缺任何一样平台都不完整。
