# P7 架构与技术选型

> **结论先行**:书域 = 1 个 Android 客户端 + 5 个 Spring Boot 微服务 + RabbitMQ + 2 个 MySQL + Redis + 向量库,全部容器化。选型原则:"栈已验证过,不引入未知技术"。

## 二、技术选型表

### 后端

| 选型 | 为什么 |
| --- | --- |
| **Java 21** | 本机已装;Spring Boot 3 需要 Java 17+ |
| **Spring Boot 3** | 用户中心已验证;JPA/Security 开箱即用 |
| **Spring Data JPA** | CRUD 场景足够;比 MyBatis-Plus 少写配置 |
| **JWT(jjwt)** | 无状态;适合 App↔微服务;用户中心已验证 |
| **RabbitMQ** | 训练课题原文指定;fanout 模式;比 Kafka 轻量 |
| **Spring AI** | 课件有专章;统一抽象;内置 RAG(VectorStore 接口) |
| **DeepSeek** | 国内可访问;性价比高 |
| **SimpleVectorStore** | Spring AI 内置;MVP 够用;接口切换不改代码 |

### 前端(App)

| 选型 | 为什么 |
| --- | --- |
| **Kotlin** | Android 官方;旧项目已是 Kotlin |
| **Jetpack Compose** | 声明式 UI;比 XML 高效 |
| **Room** | 旧项目完整实体可迁移;类型安全 |
| **Hilt** | Compose 原生集成;编译期安全 |
| **Retrofit + OkHttp** | Android 网络层事实标准 |
| **DataStore** | 替代 SharedPreferences;协程安全 |

### 基础设施

| 选型 | 为什么 |
| --- | --- |
| **Docker Compose** | 用户中心已验证;一条命令起平台 |
| **MySQL 8** | 用户中心已验证 |
| **Redis** | 用户中心已验证(JWT 黑名单) |

**选型原则**:每项必须满足①用户中心已验证 ②课件要求 ③旧项目有资产——三个条件至少一个。不满足的不引入。

**关于 Spring Cloud**:PPT 参考页提到的 Gateway/Config Center 适用于 10+ 微服务集群。书域 5 个服务,Docker Compose DNS 做服务发现已足够——这符合课件"从简到繁,先单体后拆分"的思路。

## 四、AI 应用说明

**结论:书域使用 DeepSeek + Spring AI + RAG 架构,将公版书章节向量化后实现划词即问。**

**根据**:结课设计明确要求 AI 应用说明;AI 超级智能体参考项目的 RAG 教程验证了"向量库 + LLM 问答"技术路线的可行性;Spring AI 的 VectorStore 接口使换模型和换向量库都不改业务代码。

**具体应用**:
1. **RAG 问答**:章节分段→Embedding→向量库;读者划词→检索→组 prompt→LLM 回答(附原文引用)
2. **章节摘要**:章节全文→LLM→结构化摘要
3. **向量入库**:管理员上传书→回调 AI 服务→批量 Embedding→入库

## 五、关键技术点

**结论:最出彩是 RAG 问答嵌入阅读器,最关键(对训练课题)是登录事件异步解耦。**

### RAG 问答(最出色)

**问题**:LLM 会编造书中不存在的内容;移动端 AI 调用 >3s 影响阅读流。
**方案**:先向量化入库,提问时检索相关段落喂给 LLM,强制引用原文。降级:向量库未覆盖时仅用选中文本+问题发 LLM。

### 登录事件异步解耦(最关键,训练课题原文)

**问题**:登录响应必须 <1s,但训练课题要求 fanout 到两个 queue。
**方案**:`@Async` 发布事件,同步只返回 JWT;fanout 到 login.log + login.stats,两个消费者独立处理。RabbitMQ 宕机也不阻塞登录(事件入本地缓冲,重试 3 次后入死信)。

**例子**:读者点登录,半秒拿到 JWT 进入书架;统计服务的 +1 操作在后台异步完成——这就是训练课题说的"分布式事件驱动"在真实产品里的样子。

### Room 离线缓存(最影响体验)

**问题**:章节内容可能被更新,但用户期望离线也能读。
**方案**:首次在线加载→Room 缓存;再次打开→查 Room(7 天有效)→直接渲染。超期重新拉取,LRU 清理。
