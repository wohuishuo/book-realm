# P7 架构与技术选型

> **结论先行**:书域 = 1 个 Android 客户端 + 5 个 Spring Boot 微服务 + RabbitMQ + 2 个 MySQL + Redis + 向量库,全部容器化。选型原则是"栈已验证过,不引入未知技术"。

## 二、技术选型表

### 后端

| 项 | 选型 | 为什么 |
| --- | --- | --- |
| 语言 | Java 21 | 本机已装;Spring Boot 3 需要 Java 17+ |
| 框架 | Spring Boot 3 | 用户中心已验证;JPA/Security/Actuator 开箱即用 |
| ORM | Spring Data JPA | 用户中心已验证;CRUD 场景足够;比 MyBatis-Plus 简单 |
| 认证 | JWT(jjwt) | 无状态,适合 App↔微服务;用户中心已验证 |
| 消息队列 | RabbitMQ | 训练课题原文指定;fanout 模式;比 Kafka 轻量 |
| AI 框架 | Spring AI | 课件有专章;统一抽象;内置 RAG(VectorStore 接口) |
| LLM | DeepSeek | 国内可访问;性价比高 |
| 向量库 | SimpleVectorStore(内存) | Spring AI 内置;MVP 演示够用;接口切换不改代码 |

### 前端(App)

| 项 | 选型 | 为什么 |
| --- | --- | --- |
| 语言 | Kotlin | Android 官方推荐;旧项目已是 Kotlin |
| UI | Jetpack Compose | 声明式 UI;比 XML 高效 |
| 本地存储 | Room | 旧项目已有完整实体可迁移 |
| DI | Hilt | Compose 原生集成;编译期安全 |
| 网络 | Retrofit + OkHttp | Android 网络层事实标准 |
| Token 存储 | DataStore | 替代 SharedPreferences;协程安全 |

### 基础设施

| 项 | 选型 | 为什么 |
| --- | --- | --- |
| 容器化 | Docker Compose | 用户中心已验证;一条命令起平台 |
| 数据库 | MySQL 8 | 用户中心已验证;课件以 MySQL 为主 |
| 缓存 | Redis | 用户中心已验证(JWT 黑名单) |

**关于 Spring Cloud**:PPT 参考页提到的 Gateway/Config Center 适用于 10+ 微服务集群。书域 5 个服务,Docker Compose DNS 做服务发现已足够,不引入 Spring Cloud 避免过度设计——这符合课件"从简到繁,先单体后拆分"的思路。

### 选型原则

每项技术必须满足至少一个条件:①用户中心已验证 ②课件要求 ③旧项目有资产。不满足的不引入。这避免了上学期"学满课件才动手→只完成数据库"的教训。

## 四、AI 应用说明

**书域使用 DeepSeek + Spring AI + RAG 架构,将公版书章节向量化后实现划词即问。**

**根据**:结课设计明确要求 AI 应用说明;AI 超级智能体参考项目的 RAG 教程(第 4、5 章)验证了"本地向量库 + LLM 回答"的技术可行性;Spring AI 的 VectorStore 接口使换模型和换向量库都不改业务代码。

**三个具体应用**:
1. **RAG 读书问答**:章节分段→Embedding→SimpleVectorStore;划词提问→向量检索→组 Prompt→LLM 回答(附原文引用)
2. **章节摘要**:章节全文→LLM 摘要 Prompt→结构化摘要
3. **向量入库**:管理员上传书→书库回调 AI 服务→批量 Embedding→向量库

## 五、关键技术点

**书域最出彩的是 RAG 读书问答嵌入阅读器,最关键的是登录事件驱动的异步解耦(对应对训练课题)。**

### 关键点一:RAG 问答(最出色)

**问题**:LLM 会"编造"书中不存在的内容,移动端 AI 调用 >3s 影响阅读流。
**方案**:先向量化入库(RAG),提问时检索相关段落喂给 LLM,强制引用原文。降级:向量库未覆盖时仅用选中文本+问题发 LLM。
**对应**:见 P6 图三顺序图。

### 关键点二:登录事件异步解耦(最关键,训练课题原文)

**问题**:登录响应必须 <1s,但训练课题要求 fanout 两个 queue。
**方案**:用户中心 `@Async` 发布事件,同步只返回 JWT;RabbitMQ fanout 到 login.log + login.stats,两个消费者独立处理。
**对应**:见 P6 图一顺序图。

### 关键点三:Room 离线缓存(最影响体验)

**问题**:章节内容可能被管理员更新,但用户期望离线也能读。
**方案**:首次在线加载→Room 缓存;再次打开→查 Room(7 天内有效)→直接渲染;超期重新拉取。LRU 清理。
